## The thing to decide next: F-017

Adding EBV type 2 (`NC_009334.1`, my `CAT-32`) has a cost the build itself
cannot see:

> 16 % of EBV molecules (146,634 / 906,606) move onto type 2, and 99 % of that
> mass is an **equal split of EBV-1/EBV-2 shared ECs** — despite unique support
> of 183,964 vs 1,357 (136 : 1) in favour of type 1. The EBV 1+2 total is
> unchanged (+0.04 %); HSV-1 and the HHV-2 bleed flag are unaffected.

So type 2 is now *detectable* but *mis-assigned* roughly 16 % of the time. The
concurrent session's recommendation, which I have **not** acted on: do not ship
the max panel as default until siblings group via a Virus Identity table and
detection aggregates at virus level. Read F-017 and decide.

Related, not yet measured (F-017 says to measure it): near-identical sibling
pairs in the new panel — HPV same-type pairs, OC43 ×2, 18 SARS-CoV-2 records.

## Pitfalls that cost real time this session

1. **`kb` exits 0 after kallisto fails.** `build_reference.py`'s
   `CalledProcessError` handler never fires. Gate on artifacts: `panel.idx`
   non-empty, `panel.t2g` non-empty, `counts_unfiltered/` present. An earlier
   "the index built fine" read was wrong because of this.
2. **kallisto ≥0.50 writes a single-file index** — no `.td`/`.nd`. An assertion
   that those exist is wrong, not the build.
3. **kallisto and bustools are vendored inside the `kb_python` wheel.** Pinning
   conda `kallisto`/`bustools` is cosmetic; pin `kb-python` itself. The drifted
   env had conda bustools 0.45.1 on PATH while `kb` ran the bundled 0.51.1.
4. **The pinned env is Python 3.8; the repo needs 3.9+** (`dict[str, str]`).
   Working invocation: the repo's 3.12 with the pinned env's `bin` first on
   `PATH`.
5. **dustmasker masks ~0.01 % of this panel and cannot remove pure-homopolymer
   k-mers.** DUST scores compositional complexity; it is not built to strip a
   homopolymer tract. The builder now masks runs of ≥31 identical bases directly.
   Do not "fix" this by re-enabling dustmasker alone.
6. **The shipped covid `index.idx` is healthy.** The old crash was in `kb ref`
   *rebuilding*: `combined.gtf` is chromosomal (seqnames 1..22) paired with a
   cDNA FASTA keyed by ENST. Point at `combined_cdna.gtf`, and preflight that
   every GTF seqname exists as a FASTA record.
7. **A subagent hallucinated accessions despite explicit instruction** — it
   reported `NC_001856.1` as a polyomavirus (it is *Borrelia burgdorferi*),
   `NC_014968.1` as HCoV-OC43 (a sweet-potato plant virus), `NC_007455.1` as EBV
   (a bocavirus). On any curation task, **verify the returned `DEFINITION`
   string** against the intended organism. A plausible accession resolves to a
   real but wrong organism.
8. **A scratch dir inside the repo got wiped mid-session** (likely a mycelium
   `PostToolUse` hook): `ViralScan/work/` and everything two agents wrote there
   vanished, while the conda env and repo edits survived. Agent output now goes
   to `viral_ref_final/` outside the repo. Keep it that way.
9. **Accessions appear in three formats** — `NC_007605.1`, `NC 007605.1` (space,
   in VIRTUS2's list), and bare `M74117`. Compare on the version-stripped,
   underscore-normalised base. `normalise_accession()` in `build_reference.py`
   does this; a naive regex gave a wrong answer twice.
10. **`anellovirus_accessions.tsv` is CRLF.** Rewriting it with a naive Python
    script converts the whole file and produces a 4,085-line diff for a one-row
    change. Preserve line endings.

## Retractions — do not re-cite these

- **F-015 originally reported 92 HPV types and 76 new.** Wrong: the regex
  `HPV\d{1,2}` missed every three-digit type. Correct: **182 types, 166 new**
  (16 already catalogued by type). Corrected in place.
- "index = 7.7 % of the catalogue" and "0.5 % anellovirus in the index" were
  **header-parsing artifacts** and were retracted. The family-level gaps
  (13/16 HPV, 5/5 Retroviridae missing) are sound; those were computed as
  "is this catalogued accession present in the built FASTA".
- An earlier subagent report claimed "77 % of EBV1 31-mers are type-1-unique".
  **Wrong direction.** Measured: 79.9 % *shared*, 20.1 % type-1-unique.
- Claims that raw `-x` or particular N values caused the `kb` failure were
  retracted after malformed command-line testing.

## Things that are settled, do not re-open

- **CAT-05**: `NC_038359.1` and `AB303562.1` are byte-identical (3,187 bp, taxid
  2065053, isolate MDJN51, md5 `5e78d2d32ea911d61962cd8ad6255a4f`). RefSeq's own
  COMMENT says so. Kept the RefSeq copy (4 curated genes), dropped the GenBank
  twin. Table is 2,041.
- **CAT-31**: the guard works and runs *before* `kb ref`, so a lossy panel fails
  in seconds rather than after ~64 GB. Its allowlist ships **empty on purpose** —
  pre-allowlisting the 34 gaps would turn a red build green without a genome.
- **CAT-34**: closed negative. The D-list genome (`refdata-gex-GRCh38-2024-A`,
  194 contigs) and the GRCh38.116 GTF contain **zero** viral contigs, so the
  `chrEBV` silent-invisibility hazard does not apply. Re-check on a host swap.
- **HPV multimapping is a non-issue** (measured, not assumed): 98.68 % of k-mer
  space is type-discriminating, min unique-31-mer fraction 0.867, HPV16/HPV18
  share *zero* 31-mers, L1 is *more* type-specific than non-L1 (0.9838 vs
  0.9683), and 100-nt read assignability is 99.96 %. Caveat: this is computed
  outside kallisto and cannot see the pseudo-inverse threshold effect — which is
  what F-017 shows actually bites.
- **20 duplicate `transcript_id`s** across the bundled GTFs were a live
  `SegmentCollection.copy` crash; 301 occurrences namespaced across 111 files,
  re-scan clean.
- **EBER1/EBER2** were silently dropped by a `key == "CDS"` filter. Fixed; the
  regenerated EBV GTF has 96 genes (94 CDS + 2 EBER), matching VIRTUS3's
  independent 96-record reference.
